# Database Architecture (Part 2.4 — File Intelligence, Storage & Knowledge Architecture)

**Document Version:** 1.0
**Project:** MindMesh – AI-Powered Knowledge Intelligence System

---

## Purpose
This document defines the complete File Intelligence database architecture of MindMesh. MindMesh treats every uploaded file as an intelligent knowledge asset, supporting previews, text chunks extraction, AI summarization, semantic embeddings mapping, and universal search.

---

## Database Tables

### 1. `files` Table
* **Purpose**: Primary file entry metadata. actual binary bytes are saved on disk / object storage.
* **Columns**:
  * `id`: UUID (PK, Version 7)
  * `workspace_id`: UUID (FK -> `workspaces.id`, CASCADE)
  * `project_id`: UUID (FK -> `projects.id`, CASCADE, NULLABLE)
  * `conversation_id`: UUID (FK -> `conversations.id`, CASCADE, NULLABLE)
  * `uploaded_by`: UUID (FK -> `users.id`, RESTRICT)
  * `current_version_id`: UUID (NULLABLE initially, updates to track the active row in `file_versions`)
  * `filename`: VARCHAR(255) (NOT NULL)
  * `original_filename`: VARCHAR(255) (NOT NULL)
  * `extension`: VARCHAR(50) (NOT NULL)
  * `mime_type`: VARCHAR(100) (NOT NULL)
  * `file_size`: BIGINT (NOT NULL - size in bytes)
  * `checksum`: VARCHAR(64) (NOT NULL - SHA-256 hash for duplicate check)
  * `storage_path`: TEXT (NOT NULL - path relative to disk root)
  * `visibility`: FileVisibility ENUM (PRIVATE, WORKSPACE, PROJECT, PUBLIC_LINK)
  * `created_at`: TIMESTAMP (NOT NULL)
  * `updated_at`: TIMESTAMP (NOT NULL)
  * `deleted_at`: TIMESTAMP (NULLABLE)

### 2. `file_versions` Table (Upload History Audit)
* **Purpose**: Tracks previous uploads of the file to support rollbacks and change audits.
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `version_number`: INT (NOT NULL - 1, 2, 3...)
  * `storage_path`: TEXT (NOT NULL)
  * `checksum`: VARCHAR(64) (NOT NULL)
  * `uploaded_by`: UUID (FK -> `users.id`, RESTRICT)
  * `change_notes`: TEXT (NULLABLE)
  * `created_at`: TIMESTAMP (NOT NULL)

### 3. `file_metadata` Table
* **Purpose**: Stores technical specifications (e.g. image dimensions, page counts, CAD parameters).
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `metadata`: JSONB (NOT NULL - stores structural key-value specs)
  * `created_at`: TIMESTAMP, `updated_at`: TIMESTAMP

### 4. `file_previews` Table
* **Purpose**: Tracks asynchronous generated thumbnails, wave previews, or PDF snapshots.
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `preview_data`: JSONB (NOT NULL - stores preview URLs, types, dimensions)
  * `created_at`: TIMESTAMP, `updated_at`: TIMESTAMP

### 5. `file_tags` Table
* **Purpose**: Stores user-assigned categories (Invoices, Code, Research, Designs).
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `tag_name`: VARCHAR(100) (NOT NULL)
  * `created_at`: TIMESTAMP (NOT NULL)
* **Indexes**: Composite index on `(file_id, tag_name)` (UNIQUE)

### 6. `knowledge_chunks` Table (Text Extraction Pieces)
* **Purpose**: Stores parsed text chunks extracted from documents.
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `chunk_index`: INT (NOT NULL - sequential index 0, 1, 2...)
  * `text`: TEXT (NOT NULL - chunk contents)
  * `token_count`: INT (NOT NULL)
  * `page_number`: INT (NULLABLE)
  * `section_title`: VARCHAR(255) (NULLABLE)
  * `created_at`: TIMESTAMP (NOT NULL)

### 7. `file_embeddings` Table (Vector Index Mapping)
* **Purpose**: Maps database chunks to specific vector IDs in the ChromaDB instance.
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `chunk_id`: UUID (FK -> `knowledge_chunks.id`, CASCADE)
  * `embedding_provider`: VARCHAR(100) (NOT NULL)
  * `vector_id`: VARCHAR(255) (NOT NULL)
  * `model_name`: VARCHAR(100) (NOT NULL)
  * `created_at`: TIMESTAMP (NOT NULL)

### 8. `semantic_indexes` Table
* **Purpose**: Stores summaries, keywords, entity lists, and topics generated by AI.
* **Columns**:
  * `id`: UUID (PK)
  * `file_id`: UUID (FK -> `files.id`, CASCADE)
  * `index_data`: JSONB (NOT NULL - stores summaries, names, tags, dates)
  * `created_at`: TIMESTAMP, `updated_at`: TIMESTAMP

---

## Indexing Strategy
* **Foreign Keys**: `workspace_id`, `project_id`, `conversation_id`, `uploaded_by`.
* **Composite Indexes**:
  * `(workspace_id, filename)` (facilitates workspace filename lookup)
  * `(project_id, created_at)` (for project files list)
  * `(uploaded_by, created_at)` (for user profile uploads list)
